# 卫星数据报文格式说明

## 1. 数据链路

~~~text
模拟脚本或卫星模组
    ↓ 国电高科 TCP 二进制报文
阿里云服务器 139.196.214.249:8091
    ↓ HTTP POST JSON
目标服务器 47.99.47.169:11503
~~~

模拟脚本不是直接发送裸 JSON，而是将紧凑 JSON 放入 TCP 二进制报文的 Content 字段。

## 2. 当前转发白名单

阿里云当前只向目标服务器转发以下卫星模组 SN：

~~~text
11309
11310
11311
11078
11315
~~~

SN 的前导零会被忽略，例如 00011309 与 11309 等效。

11279 已从阿里云转发白名单和本地模拟脚本映射中移除。它的报文即使被阿里云接收并保存，也不会再转发。

## 3. 模拟脚本的网关映射

| 网关 | 卫星模组 SN | 当前数据 |
|---|---:|---|
| gateway1 | 11309 | 温湿度、火情跳变 |
| gateway2 | 11310 | 风速 |
| gateway3 | 11311 | 火情 |
| gateway5 | 11078 | 已配置 SN，默认批次暂不生成数据 |
| gateway4 | 无 | 原 11279 映射已删除 |

11315 在阿里云转发白名单中，但当前模拟脚本未给它配置网关映射。

## 4. 卫星业务 JSON

### 4.1 通用结构

~~~json
{
  "t": "YYMMDDhhmmss",
  "s": "传感器类型",
  "v": "传感器值",
  "g": 1
}
~~~

| 字段 | 类型 | 含义 |
|---|---|---|
| t | 字符串 | 采集时间，格式 YYMMDDhhmmss |
| s | 字符串 | 传感器类型：TH、F 或 WS |
| v | 对象、布尔值或数值 | 传感器值 |
| g | 整数 | 网关编号 |

实际发送时使用 UTF-8 编码，并删除不必要的空格。

### 4.2 gateway1 温湿度

~~~json
{"t":"260812103351","s":"TH","v":{"tp":23.4,"rh":82.1},"g":1}
~~~

约束：

- s 必须为 TH。
- g 必须为 1。
- v.tp 为温度数值，范围 -50～100，单位 °C。
- v.rh 为相对湿度数值，范围 0～100，单位 %。

### 4.3 gateway1 火情跳变

发生火情：

~~~json
{"t":"260812103351","s":"F","v":true,"g":1}
~~~

解除火情：

~~~json
{"t":"260812103351","s":"F","v":false,"g":1}
~~~

gateway1 火情状态只在状态变化时立即发送。首次输入状态只建立基准，不发送报文。

### 4.4 gateway3 火情

发生火情：

~~~json
{"t":"260812103351","s":"F","v":true,"g":3}
~~~

解除火情：

~~~json
{"t":"260812103351","s":"F","v":false,"g":3}
~~~

约束：

- 火情类型为 F。
- 火情只允许使用 g=1 或 g=3。
- v 必须是 JSON 布尔值 true 或 false，不能写成字符串。

### 4.5 gateway2 风速

~~~json
{"t":"260812103351","s":"WS","v":24.5,"g":2}
~~~

约束：

- s 必须为 WS。
- g 必须为 2。
- v 必须是大于或等于 0 的数值。
- 单位固定为 m/s。

## 5. Msg_id 格式

~~~text
卫星模组SN_数据上星时间_三位序号
~~~

示例：

~~~text
11309_20260812103351_214
~~~

| 部分 | 格式 | 示例 |
|---|---|---|
| 卫星模组 SN | 不带前导零的短 SN | 11309 |
| 数据上星时间 | YYYYMMDDhhmmss | 20260812103351 |
| 序号 | 三位十进制数，000～999 | 214 |

注意：Content.t 使用两位年份，Msg_id 中的时间使用四位年份。

## 6. 发给阿里云的 TCP 二进制报文

目标：

~~~text
协议：TCP
主机：139.196.214.249
端口：8091
~~~

### 6.1 字节结构

| 顺序 | 字段 | 长度 | 编码及含义 |
|---:|---|---:|---|
| 1 | Total_len | 4 字节 | 大端无符号整数，整个报文的总字节数 |
| 2 | Cmd_code | 1 字节 | 固定为 0x01，表示报文上传 |
| 3 | Token | 20 字节 | ASCII；不足部分在右侧补 0x00 |
| 4 | Msg_id_len | 1 字节 | Msg_id 的 ASCII 字节数 |
| 5 | Msg_id | 变长 | ASCII 编码的消息 ID |
| 6 | Content_len | 2 字节 | 大端无符号整数，Content 的 UTF-8 字节数 |
| 7 | Content | 变长 | UTF-8 编码的紧凑 JSON |

结构表达式：

~~~text
uint32_be(Total_len)
+ 0x01
+ Token[20]
+ uint8(Msg_id_len)
+ ASCII(Msg_id)
+ uint16_be(Content_len)
+ UTF8(JSON Content)
~~~

总长度计算：

~~~text
Total_len = 4 + 1 + 20 + 1 + Msg_id_len + 2 + Content_len
~~~

### 6.2 Token 规则

- 最长为 20 个 ASCII 字节。
- 当前模拟脚本默认 Token 为空。
- 空 Token 在报文中表示为 20 个 0x00。
- 不允许包含非 ASCII 字符。

### 6.3 Content 长度规则

- Content_len 是 JSON 经 UTF-8 编码后的实际字节数。
- TCP 字段理论上最大可表示 65535 字节。
- 当前模拟脚本额外限制卫星单帧 Content 不超过 120 字节。

## 7. 阿里云 TCP 响应

### 7.1 保存成功

~~~text
000000068100
~~~

拆分：

~~~text
00 00 00 06 81 00
~~~

| 字段 | 值 | 含义 |
|---|---|---|
| 总长度 | 0x00000006 | 共 6 字节 |
| 响应命令 | 0x81 | 上传命令 0x01 的响应 |
| Result | 0x00 | 保存成功 |

### 7.2 保存失败

~~~text
000000068101
~~~

| 字段 | 值 | 含义 |
|---|---|---|
| 总长度 | 0x00000006 | 共 6 字节 |
| 响应命令 | 0x81 | 上传命令 0x01 的响应 |
| Result | 0x01 | 解析或保存失败 |

该响应只表示阿里云接收程序已经处理并保存报文，不代表报文已经成功转发到目标服务器。

## 8. 阿里云转发给目标服务器的 HTTP 请求

### 8.1 接口

~~~http
POST http://47.99.47.169:11503/
Content-Type: application/json; charset=utf-8
~~~

只有卫星模组 SN 位于当前白名单内，并且 Content 通过业务校验时，阿里云才会发出此请求。

### 8.2 公共字段

| 字段 | 类型 | 含义 |
|---|---|---|
| gateway | 字符串 | 标准化网关名称，如 gateway1 |
| timestamp | 字符串 | 原始传感器采集时间 |
| satellite_received_timestamp | 字符串 | 从 Msg_id 提取的数据上星时间 |
| server_received_timestamp | 字符串 | 阿里云 TCP 接收时间 |
| terminal_id | 字符串 | 去除前导零后的卫星模组 SN |
| message_id | 字符串 | 原始 Msg_id |
| sequence | 字符串 | 从 Msg_id 提取的序号 |
| forwarded_timestamp | 字符串 | 执行 HTTP 转发的时间 |
| raw_content_hex | 字符串 | 原始 Content 的十六进制表示 |
| content | JSON | 原始业务 JSON |
| sensor_type | 字符串 | TH、F 或 WS |
| value | JSON | 原始传感器值 |

### 8.3 温湿度转发 JSON

~~~json
{
  "gateway": "gateway1",
  "timestamp": "2026-08-12 10:33:51",
  "satellite_received_timestamp": "2026-08-12 10:33:51",
  "server_received_timestamp": "2026-08-12T10:33:52.123+08:00",
  "terminal_id": "11309",
  "message_id": "11309_20260812103351_214",
  "sequence": "214",
  "forwarded_timestamp": "2026-08-12T10:33:52.456+08:00",
  "raw_content_hex": "7b2274223a...",
  "content": {
    "t": "260812103351",
    "s": "TH",
    "v": {
      "tp": 23.4,
      "rh": 82.1
    },
    "g": 1
  },
  "sensor_type": "TH",
  "value": {
    "tp": 23.4,
    "rh": 82.1
  },
  "temperature": 23.4,
  "humidity": 82.1,
  "temperature_unit": "°C",
  "humidity_unit": "%"
}
~~~

温湿度附加字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| temperature | 数值 | 温度 |
| humidity | 数值 | 相对湿度 |
| temperature_unit | 字符串 | 固定为 °C |
| humidity_unit | 字符串 | 固定为 % |

## 9. 旧版 Content 兼容格式

阿里云转发程序还兼容能够识别出网关、时间和火情字段的旧 JSON，例如：

~~~json
{
  "gateway": "gateway1",
  "timestamp": "2026-08-12 10:33:51",
  "fire": true
}
~~~

可识别的网关写法：

~~~text
gateway1 ～ gateway5
gw1 ～ gw5
g1 ～ g5
1 ～ 5
~~~

可识别的时间字段：

~~~text
timestamp
original_timestamp
original_time
generated_at
event_time
create_time
created_at
time
~~~

可识别的火情字段：

~~~text
fire
is_fire
fire_alarm
fire_status
alarm
火灾
火警
~~~

新开发和模拟测试应统一使用 t/s/v/g 紧凑格式。

## 10. 时间格式汇总

| 使用位置 | 格式 | 示例 |
|---|---|---|
| Content.t | YYMMDDhhmmss | 260812103351 |
| Msg_id 数据上星时间 | YYYYMMDDhhmmss | 20260812103351 |
| HTTP timestamp | YYYY-MM-DD hh:mm:ss | 2026-08-12 10:33:51 |
| HTTP satellite_received_timestamp | YYYY-MM-DD hh:mm:ss | 2026-08-12 10:33:51 |
| HTTP server_received_timestamp | ISO 8601，包含毫秒及时区 | 2026-08-12T10:33:52.123+08:00 |
| HTTP forwarded_timestamp | ISO 8601，包含毫秒及时区 | 2026-08-12T10:33:52.456+08:00 |

## 11. 转发校验规则

阿里云转发新格式报文前，需要同时满足：

1. TCP 二进制报文长度及字段结构正确。
2. Cmd_code 为 0x01。
3. Msg_id 符合“终端编号_YYYYMMDDhhmmss_序号”格式。
4. 卫星模组 SN 位于当前转发白名单。
5. Content 是合法的 UTF-8 JSON。
6. Content 同时包含 t、s、v、g。
7. t 是有效的 YYMMDDhhmmss 时间字符串。
8. s 只能为 TH、F 或 WS。
9. TH 只能来自 gateway1，且 tp、rh 范围正确。
10. F 只能来自 gateway1 或 gateway3，且 v 为布尔值。
11. WS 只能来自 gateway2，且 v 是非负数值。
